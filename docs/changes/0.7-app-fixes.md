# 0.7 — App fixes (route search & history)

Stream owner: orchestrator. Branch: `wave/0.7-obd-ux`.

## 1. History "saved" amount ignored the route the user picked

**Problem.** `RouteViewModel.runSearch` stored `savedAmount = fastest.totalCost - ranked[0].totalCost`.
`persistSelection` later updated `selectedPredictedCost` when the user chose another route, but never
the savings. History (`DriveHistoryRepository.toEntry`) showed and summed `savedAmount` as stored, so
driving the fastest route still counted as a saving.

**Fix.** `DriveHistoryRepository.toEntry` now derives the saving from the stored `fastestCost` and the
cost of the route actually selected: `max(0, fastestCost - selectedCost)`. Legacy rows without a
selection fall back to `cheapestCost`, which gives the old value. Rows with no `fastestCost`
fall back to the stored `savedAmount`. No schema change.

**Tests.** `DriveHistoryRepositoryTest`: "savings are measured for the selected route, not the
top-ranked one", "savings for the top-ranked route are fastest minus cheapest".

## 2. Route searches could race

**Problem.** Each `compute()`/`refresh()` launched an independent coroutine. Two searches in flight
(for example tapping a favorite, then Refresh) let whichever finished last overwrite the results. Each
also wrote its own `route_search` row, and `lastSearchId` could point at the wrong search.
`catch (Throwable)` also swallowed `CancellationException`.

**Fix.** `RouteViewModel` keeps a `searchJob` and cancels it before starting a new search. It clears
`lastSearchId` so the old search can't receive the new selection, and rethrows
`CancellationException`. The duplicate `DEFAULT_FUEL_PRICE` constant was replaced by
`ModelConstants.DEFAULT_FUEL_PRICE`.

**Tests.** New `RouteViewModelSearchTest`: a slow first search is superseded by a refresh, and when it
completes late it neither overwrites the fresh result nor writes a second history row.

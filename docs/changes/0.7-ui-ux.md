# 0.7 — UI/UX redesign ("calm, clear, fast")

Stream: **ui-ux**. Base: `master` @ 69716d7 (v0.6.4), then merged `wave/0.7-obd-ux`.
Scope: every composable under `ui/**`, `ui/theme`, new `ui/components/`, `nav/FuelRouteNavHost.kt`,
`res/values*/strings*.xml`, `res/drawable`. No ViewModel, `domain/`, `data/`, `service/` or `car/`
logic was changed.

User feedback that started this: *"the UI is crowded, the UX is not good."*

---

## 1. Audit (of the 0.6.4 screens)

### Across the app
- **No shared building blocks.** Each screen re-implemented cards, `InfoColumn`, `format()`,
  confirmation dialogs (5 near-identical copies), load-error cards (3 identical copies) and
  expand/collapse rows (4 different implementations: `SettingsSection`, `ExpandableSettingsRow`,
  `DiagnosticsCard`, calibration "מתקדם").
- **No spacing scale.** Paddings of 12/16/24 dp and gaps of 4/6/8/10/12/14/16 dp were mixed freely.
- **Flat hierarchy.** Almost everything was `bodyMedium`/`labelSmall`; important facts (toll hints,
  fuel price, "based on N km") were in the smallest style while decoration was large.
- **No top bar / no back affordance** on pushed screens (history, curve, refuel, calibration) —
  only the system back gesture.
- **Colour.** Dynamic (wallpaper) colour made "green = cheapest" arbitrary on Android 12+; the
  static light scheme only set primary/secondary/tertiary, so containers fell back to baseline
  purple. Four files hardcoded hex colours with their own `isSystemInDarkTheme()` branches.
- **Tab icons** did not mean anything (Build = vehicle, List = stats).
- **Feedback** was a mix of Toast, inline text that shifted the list, and nothing.

### Route (1652 lines)
- Before the first result the user faced ~10 controls: origin field + "current location" text
  button, destination (star + clear), favorites header + chips with nested 18 dp "⋮" icons,
  recents chips with nested 18 dp star icons, departure outlined button + "now" button, compute
  button, a "refresh" text button of equal weight, the fuel-price caption, and "previous searches".
- Results repeated themselves: a summary card (cheapest / fastest / trade-off), an expandable
  speed-graph card with a permanent explanatory paragraph, then one card per route with ~14 lines
  (3 text badges, price, time, toll line + toll hint, Δ cost, Δ time, divider, 3 + 2 info columns
  — total cost printed twice — reason line, traffic-resolution label).
- **Navigate was two taps away**, inside a dialog that also duplicated the speed graph.

### Stats / live OBD (991 lines)
- Title, vehicle chips, a full-width "curve" button, an auto-logging status card (4 lines, a copy
  of the one in Settings) and a connection status card all came *before* the state-specific UI.
- Connected: 9 stacked blocks (speed gauge, consumption tiles, trip card, engine chips, range,
  learned data, diagnostics, disconnect + **reset as a peer of disconnect**).
- Disconnected: the demo button was a filled primary button — more prominent than the real dongles.
- Raw ELM diagnostics (raw reply, PIDs, VIN) sat in the status card for normal users.

### History (1052 lines)
- Each ride card: up to 12 text lines plus 3 outlined buttons (manual cost, merge/split, link)
  and a red delete icon — the list was a wall of buttons.
- Accuracy and total saved were two `titleSmall` lines under the title; link/merge feedback was
  inline text that pushed the list down.

### Curve (1044 lines)
- Summary card of 8 lines, including a long quality-threshold paragraph; chart card with two more
  paragraphs; four full-width stacked buttons where **"adopt learned" (destructive) was the most
  prominent filled button**.

### Settings (847 lines)
- Six collapsible sections, some with a second collapsible inside; the auto-logging status card
  (duplicate of Stats); retention as five chips; a 12-line Android Auto card and the full
  changelog printed inline.

### Vehicle / Refuel / Calibration / Onboarding
- Vehicle: units were only inside long labels; **no validation** — engine displacement typed in
  cc (1800) into a litres field made fuel rates 1000× too high.
- Refuel: correction factor as a caption; history as full cards.
- Calibration: dense but structured; mostly needed the shared shell.
- Onboarding: fine; only restyled.

## 2. Design principles applied

1. **One primary action per screen/card** (filled 56 dp button). Everything else is secondary
   (outlined), tertiary (text) or in an overflow menu.
2. **One hero number** per screen: route total ₪, live consumption + trip ₪, money saved, most
   efficient speed.
3. **Progressive disclosure**: diagnostics, engine details, learning stats, model explanations,
   per-segment tables, destructive data actions → `ExpandableSection`, bottom sheets, overflow
   menu or Settings › Advanced.
4. **A small shared vocabulary** (`ui/components`) and a 4-point spacing scale (`Dimens`).
5. **Fewer words**: labels lost their embedded units (units moved to field suffixes), long help
   paragraphs moved behind "איך העקומה מחושבת?"/sheets.
6. **Driving-adjacent ergonomics**: ≥48 dp targets everywhere (no nested icons in chips), 56 dp
   primary buttons, whole-row toggles (`SwitchRow`), big tabular numbers.
7. **RTL-correct**: auto-mirrored back/chevron icons, charts forced LTR (distance/speed axes),
   Western digits via `Locale.US` formatting.
8. **Theme-driven colour**: full green tonal light/dark schemes + `FuelTheme.colors` semantic
   palette (positive/caution/negative/neutral, traffic levels, chart series). Dynamic colour off
   by default so green keeps meaning "cheap/saving".

## 3. New shared components (`app/src/main/java/com/fuelroute/ui/components/`)

| Component | Purpose |
|---|---|
| `Dimens` | Spacing scale (4/8/12/16/24), 48 dp touch target, 56 dp rows/buttons |
| `FuelTopBar` | Top bar for every screen; back arrow (auto-mirrored) on pushed screens |
| `SectionTitle` | Group heading (primary colour, semantic heading) with optional trailing action |
| `SectionCard` | The single card style (tonal surface, 16 dp padding, 12 dp rhythm, optional header / onClick) |
| `ExpandableSection` | Progressive disclosure card, 56 dp header, state announced to TalkBack, survives rotation |
| `ListRow` | Standard 56 dp row: leading icon, title/subtitle, trailing content, optional click |
| `SwitchRow` | Whole-row toggle (`Role.Switch`) |
| `KeyValueRow` | "label …… value" breakdown line |
| `HeroValue` | Screen hero number with unit + label, read as one phrase |
| `StatTile` | Metric tile, `large` for the live dashboard |
| `StatusPill` | Small tonal badge (`PillTone`: Positive / Neutral / Caution / Negative / Accent) |
| `StatusDot` | Connection state dot |
| `PrimaryButton` / `SecondaryButton` / `TonalButton` | 56 dp full-width primary/secondary, tonal |
| `ConfirmDialog` | The one confirmation dialog; destructive confirms in `error` colour |
| `ErrorCard` | Inline failure with optional Retry (route errors, load errors) |
| `EmptyState` | Quiet centred "nothing yet" block |
| `Formatters.kt` | `fmt`, `money` ("₪12.30"), `signed`, `formatDate/Time/DateTime`, `DASH` |
| `ComponentPreviews.kt` | Light/dark Hebrew previews of all of the above |

Theme (`ui/theme`): `LightColors`/`DarkColors` (complete M3 schemes from the #1B6B4A seed),
`FuelColors` + `FuelTheme.colors`, `Shapes` (16/24 dp cards), slightly heavier title weights.
Window backgrounds in `themes.xml` match the new surfaces (no flash on launch).

Icons: only `material-icons-core` is a dependency, so 10 Material glyphs were vendored as vector
drawables (`ic_car`, `ic_speed`, `ic_navigation`, `ic_history`, `ic_gas_station`, `ic_my_location`,
`ic_bluetooth`, `ic_schedule`, `ic_show_chart`, `ic_tune`).

## 4. Screens — before / after

### Navigation
- Before: tabs מסלול / רכב / סטטיסטיקה / הגדרות with Place / Build / List / Settings icons; pushed
  screens without a top bar.
- After: tabs **מסלול / נסיעה / רכב / הגדרות** (navigation / speedometer / car / tune icons) in task
  order — plan, drive, car, settings. Every pushed screen has a `FuelTopBar` with back.
  The curve is reachable from both "נסיעה" (top-bar chart icon) and "רכב".

### Route
- **Search card**: origin field whose trailing icon *is* "use my location" (and the origin is
  pre-filled with the current location once, only if permission was already granted — no prompt
  on open); destination with star + clear; a single departure chip ("יציאה: עכשיו", × to reset);
  one primary "חשב מסלולים". IME "search" on the destination runs the search.
- **Quick destinations**: one horizontal row — favorites (★, one tap = search), then recents
  (🕘, one tap = search). No nested icons. "ניהול" opens the destinations manager.
- **Results**: map, then a collapsed one-line search summary ("to X · from Y · leave now", tap to
  change), then the **hero card** of the selected route (recommended by default): route number
  (same colour as its polyline), pills (מומלץ / הזול ביותר / המהיר ביותר), big ₪ total + minutes,
  "35.2 ק״מ · הגעה 17:45", the trade-off sentence in green ("חוסך ₪4.10 מול המהיר · +6 דק׳"), a
  toll note only when relevant, and **Navigate (one tap)** + "פרטים".
- **All routes**: compact selectable rows — number dot, label, "הזול ביותר · +4 דק׳" /
  "+₪2.10 · המהיר ביותר", ₪ and minutes. Selecting one updates hero + map.
- Footer: fuel price, "based on N km"/default-curve note, single-route notice, Refresh.
- **Detail sheet** (bottom sheet): Navigate + "יצאתי במסלול הזה", cost breakdown
  (fuel L × ₪/L, toll, total), trip data (time, distance, avg speed, ETA, traffic resolution),
  speed-vs-distance graph (LTR, themed traffic colours), per-segment table (expandable), Waze note.
- Error card with a real Retry button for retryable errors; hints for quota/key/time errors.

### Destinations manager (`FavoritesScreen`)
- Full-screen with top bar. Favorites: tap to rename; ↑ / ↓ / delete as 48 dp buttons (delete
  confirmed). Recents: ★ to save. (Previously rename/delete lived in a chip's 18 dp "⋮" and
  star-a-recent in an 18 dp chip icon.)

### Drive (was "סטטיסטיקה")
- **Connection card first**, one line of state + a status dot and exactly one primary action:
  disconnected → "התחבר ל־<last dongle>" (with "דונגל אחר" / "הדגמה" as text buttons, device list
  with ★ favorites on demand); connecting → stage · elapsed seconds + "ביטול"; connected →
  device name + "התנתק"; failed → human reason + "נסה שוב" (+ other dongle / demo).
  The auto-logging state is one subtitle line ("הרישום יתחיל לבד כשהדונגל יתחבר").
- **Live dashboard**: two large tiles — live consumption (`LiveConsumptionTile`) and trip ₪
  (with litres) — and three small ones: speed, distance, minutes.
- Collapsed: **מנוע ודלק** (fuel rate, RPM, coolant, battery, fuel level, range; range also shown
  as the collapsed subtitle), **נתוני למידה**, **אבחון ופעולות מתקדמות** (last error, raw reply,
  sample rate, VIN, PIDs, the full auto-logging record, and "אפס רישום" with confirmation;
  auto-expanded on error).
- Recent trips: 5 compact rows (date, km · min · prediction, L/100 trailing), "הצג הכל (N)".
- Vehicle switcher moved to a top-bar dropdown (only with >1 vehicle).

### History
- Top bar with back and "בחר"/"סיום". A hero summary: **"חסכת עד כה ₪X"**, accuracy, ride count.
- Each ride: title (route / "נסיעה ללא חיפוש"), date · km, big ₪ (actual, else predicted, labelled)
  and ≤4 pills (state, demo, manual, prediction error %, saving).
- Tap → **ride sheet** with the predicted-vs-actual breakdown and all actions as rows: enter actual
  cost, link to a search, merge/split, delete (red, confirmed).
- Selection mode: checkbox rows + a "נבחרו N · מחק את הנבחרים" bar.
- Link/merge/split feedback via Snackbar instead of inline text.

### Curve
- Hero: **most efficient speed** (big) + L/100 at that speed, quality pill, "based on N km".
- Chart card with a legend showing only the series actually drawn; tap hint / bin chip.
- One visible action: "ערוך עקומה ידנית" (editor dialog unchanged).
- Adopt / reset learning / clear manual → top-bar overflow menu, all confirmed.
- "איך העקומה מחושבת?" (collapsed): learned share, samples, idle L/h, calibration factor, the
  blend formula, quality thresholds, point-size explanation.

### Vehicle
- Active vehicle card (name, "6.5 ל׳/100 ק״מ · בנזין 95 · מיכל 50 ל׳", edit) with its two tools as
  rows: **רישום תדלוק** and **עקומת הצריכה**. Other vehicles below (tap = make active; edit; delete).
  "+" in the top bar and an outlined "הוסף רכב".
- Form: segmented buttons for fuel type/grade; every numeric field states its unit in the label
  *and* as a suffix, has an example placeholder and help text, and is range-checked inline
  (`VehicleInputRules`, unit-tested): rated consumption 2–30 ל׳/100 ק״מ, tank 10–200 L,
  **displacement 0.6–8.0 L with a dedicated "looks like cc — enter 1.8" error for values ≥ 100**.
  Save is disabled while a field is flagged. Delete of the edited vehicle is at the bottom.

### Refuel
- One card: litres (suffix ליטר), total (suffix ₪, live "₪x לליטר" helper), full-tank `SwitchRow`
  with a one-line explanation, Save, current correction factor. History as compact rows with
  ₪/L. Over-capacity warning uses the shared dialog.

### Settings
- Five short groups of rows: **מחיר וניווט** (price with ₪/ליטר suffix, lock-price switch, time
  value with help, Google Maps | Waze segmented + Waze note), **רישום OBD** (first-run intro when
  needed, auto-connect switch whose subtitle carries dongle + last start, last error/permission
  hints, battery-exemption warning row, keep-screen-on, floating bubble, ELM note), **נתונים**
  (export, import, retention → radio dialog), **מתקדם** (calibration, Android Auto → sheet),
  **אודות** (version, "מה חדש" → dialog).

### Calibration / Onboarding / PermissionGate
- Calibration: top bar with back, shared cards/error card, theme colours; message moved to the top;
  refuel calibration before the raw parameters.
- Onboarding: shared cards/buttons; "סיימתי" is the primary, demo the secondary.
- PermissionGate renders inline (no card of its own) with the shared buttons.

## 6. Merge notes

- **Live consumption**: the dashboard hero is `ui/stats/LiveConsumption.kt`
  (`LiveConsumptionTile`). It is the only place that reads `instantL100`/`fuelRateLph` for the
  hero; rewire it when the OBD stream exposes smoothed L/100 / low-speed L/h.
  (`EngineSection` also shows `fuelRateLph`, and range uses `instantL100` as before.)
- **StatsViewModel / RouteViewModel / CurveViewModel / VehicleViewModel** were not modified; the
  screens use their existing public API only.
- **Vehicle validation**: presentation-only (`VehicleInputRules`, same parsing as
  `VehicleViewModel.save()`). If the OBD stream adds ViewModel-side cc→L normalisation or a
  validation error in `VehicleUiState`, prefer that state in `VehicleForm` and relax the Save gate.
- **Strings**: all new strings are in `strings.xml` under the "0.7 UI/UX redesign" comment; 88
  strings that no screen referenced any more were removed (including the 17 pre-existing
  `UnusedResources`).

## 8. Known gaps

- Not exercised on a device: sheet heights, IME behaviour of the collapsed search, and the
  LazyRow of quick destinations should get a real-device pass (RTL, large fonts, dark mode).
- The origin pre-fill uses the existing `useCurrentLocation()`; if location is slow the field shows
  empty for a moment.
- Charts (curve, speed) still draw their own axis text; not yet announced to TalkBack beyond the
  map/graph descriptions.
- Calibration received the shared shell but not a full content rewrite (it is an advanced tool).
- Feedback is still Toast on Route/Stats/Settings (Snackbar only on History); a shared message
  channel would need a ViewModel change.
- Onboarding cannot be reopened from Settings (would need a settings flag reset).

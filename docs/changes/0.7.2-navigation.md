# 0.7.2 - Navigation hand-off

## Problem
- Google Maps: `NavigationLauncher` sent 4 evenly spaced route points as `waypoints`. Maps shows each as a stop, so the driver had to deal with several stops while driving. The origin was always sent too, so even from "my location" Maps could open a preview and wait for a Start tap.
- Waze: its deep link accepts only a destination, so the chosen route was never passed on.

## What changed
| Case | Behaviour now |
|---|---|
| Chosen route is the Routes API default (`route-0`), starting from the current location | `google.navigation:q=...&mode=d`: starts turn-by-turn immediately, no stops, no preview |
| Chosen route is an alternative | `WaypointPlanner` picks the fewest waypoints (0-3, usually 1) that make Google compute the chosen route. It starts from the default route, adds the point where the chosen route deviates most, asks the Routes API for the route through it (`intermediates`, alternatives off) and repeats until the result matches (coverage >= 92% both ways within 60 m). Started with `dir_action=navigate` and no origin, so Maps navigates straight away. |
| Verification could not be completed | Best approximation is used and the user is told the route may differ slightly |
| Waze selected, alternative route chosen | Dialog: Waze picks its own route; offer Google Maps for the exact route, or Waze anyway |
| Waze selected, default route | Waze as before (destination only) |

Files: `domain/nav/WaypointPlanner.kt` (pure geometry + planner), `data/routes/NavigationPlanner.kt`, `RoutesRequestFactory` / `RouteRequestOptions.via` (intermediates), `CachingRoutesRepository` (via in the cache key), `nav/NavigationUris.kt` + `NavigationLauncher.kt`, `RouteViewModel.planNavigation`, `RouteScreen`.

## Tests
`WaypointPlannerTest` (7: identical route, one detour, two detours in order, service ignoring waypoints, fetch failure, tolerance, geometry), URI tests, request-factory tests. Suite: 494 tests, 0 failures, lint 0 errors.

## Limits
- Google Maps' URL scheme cannot pass a route, only stops, so an alternative still shows 1-2 intermediate points ("no need to stop" is shown in a message). Exact zero-stop navigation on an alternative would need in-app turn-by-turn guidance (not built).
- Waze cannot be given a route at all.
- Not tried on a device or in a car yet.
